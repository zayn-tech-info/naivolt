# Naivolt designer handoff

## Product character

Naivolt should feel calm, exact, trustworthy, and modern. Financial information uses quiet neutral surfaces. Emerald marks the main action or selected state. Lime is only a small decorative brand spark.

## Color

| Role | Light | Dark |
| --- | --- | --- |
| Canvas | `#F7F8FA` | `#0B0D10` |
| Surface | `#FFFFFF` | `#12151A` |
| Raised surface | `#F1F3F5` | `#191D23` |
| Main text | `#101114` | `#F4F6F8` |
| Supporting text | `#5F6670` | `#A2A9B3` |
| Border | `#E4E7EB` | `#252A32` |
| Action emerald | `#0B7A53` | `#45D6A0` |
| Brand spark | `#9DDC2C` | `#B7F34A` |

Use only one filled emerald action on a screen. Do not use lime for body text, financial status, or large surfaces.

## Type

Use Instrument Sans for all interface text and money. Use tabular digits for financial values. Use Geist Mono only for OTP, PIN, wallet addresses, and transaction references.

Important sizes are 40 for display, 30 for money figures, 28 for titles, 20 for headings, 16 for body and actions, 14 for labels, and 12 for captions.

## Layout and components

Use a 4 point spacing grid. Screen gutters are 20. Card padding is 16. Section gaps are 28. Every touch target is at least 48 by 48.

Controls use a 12 point radius. Cards use 16. Sheets use 24. Full circles are reserved for icon wells, badges, and indicators.

Use neutral filled inputs with persistent labels, helper or error text, and an emerald focus ring. Use quiet hairlines instead of heavy borders or card shadows. Use Ionicons at 16, 20, or 24.

## Onboarding delivery

Please provide light and dark designs for compact, standard, and large phones. Include normal and maximum text size behavior. Show the default state, progress behavior, final action, and any permission or error state.

Motion may be expressive for brand moments, but forms must stay calm. Also provide a reduced motion version with no continuous movement, scaling, shaking, or decorative entrance.

Keep authentication separate from onboarding. The onboarding should finish by handing the user to the existing sign in and account creation screen.
